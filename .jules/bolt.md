## 2025-01-24 - [Backend Optimization and Web Capabilities]
**Learning:** In a FastAPI application that interfaces with a local LLM (Ollama) and uses SQLite for memory, the primary performance bottlenecks are often repeated I/O handshakes. Reusing TCP connections with `requests.Session` and maintaining a persistent SQLite connection significantly reduces request overhead. Furthermore, since LLM requests are blocking, using a synchronous endpoint (`def` instead of `async def`) allows FastAPI to delegate the work to a thread pool, preventing the event loop from being blocked and improving overall responsiveness. Finally, sorting by an indexed primary key (`id`) is measurably faster than sorting by a `DATETIME` column in SQLite.

**Action:** Always prefer `requests.Session()` for repeated API calls and maintain persistent database connections for high-frequency operations. Use synchronous endpoints in FastAPI for CPU-bound or blocking I/O tasks (like LLM generation) to leverage the internal thread pool.
